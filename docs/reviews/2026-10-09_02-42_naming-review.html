01Critical Findings (Honesty — Must Fix)

C1 · Lying ID

G3 names two different gates inside one document

plan line 9 (header) vs line 78 (B003)

The header defines G3 as "G3 CV-bump authority", and A11/B043 use it that way. But B003 says "Compare against the G3 spec (5 required checks + linear history + admin bypass)" — that is the branch-protection ruleset, a different artifact entirely. TODO_LIST carries the same disease from the other side (its G3 note = CV bump). An executor of B003 would compare the wrong config against the wrong spec.

Fix B003: "the G3 spec" → "the branch-protection ruleset spec". Then collapse all gates into one namespace (see H2).
C2 · False count

"the four owner-blocked rows" — the filesystem says three

plan line 24 (tier table) vs TODO_LIST.md rows 75, 81, 82

TODO_LIST has exactly 3 rows with BLOCKED status: the coverage-threshold job, the samber-do-auditlog recorder decision, and the doanalyzerv2 go-directive floor. A35 and B102 also name exactly those three. The tier table's "four" is a count from memory — violating the plan's own DoD rule: "every count derived from the filesystem, never from memory."

Fix "A25–A35 + the three BLOCKED rows (TODO_LIST 75/81/82)" — or recount and cite row numbers.
C3 · False contract

"sorted by impact, then effort" describes an ordering the table does not have

plan line 28 (Tier A heading) vs rows A03/A08

A03 is High impact at 10 minutes but sits third, behind a 30-minute and a 40-minute task; A08 is Medium impact and sits between High-impact rows. The real order is tier-grouped, then dependency-chained (A08 depends on A07). A stated sort order is a contract: an executor trusting it would start the wrong task.

Fix Heading → "ordered by tier, then dependency chain" — or actually re-sort. The dependency order is the useful one; keep it and fix the claim.

02High, Medium, Low

H1 · Axis overload

"Tier" means two unrelated axes: granularity AND impact

plan lines 5, 19–24, 30

"Tier A"/"Tier B" divide tasks by size (30–100 min vs ≤12 min); the Tier column's "1% / 4% / 20% / tail" divides by impact. The doc is forced into ambiguous phrases like "a 20% Tier B row". Two axes, one word — the classic split brain, at the document's own organizational level.

Fix Granularity axis → Track A / Track B (or "Deep tasks / Micro-tasks"); keep the percentages as the one and only meaning of "tier".
H2 · Double naming

The push gate is named G1 and Q1 in the same sentence

plan line 9: "G1 push (Q1), release vehicle (Q2), hook-panic semantics (Q3), G2…, G3…"

Owner-blocking decisions carry two overlapping ID namespaces: G-numbered (G1–G3) and Q-numbered (Q1–Q3). G2/G3 have no Q aliases; Q2/Q3 have no G aliases; nothing maps them. A reader must hold both schemes and the alias table in their head.

Fix One namespace, one table, defined once in the plan: e.g. G1 push, G2 upstream filings, G3 CV bump, G4 release vehicle, G5 hook-panic semantics, G6 branch-protection spec.
H3 · Ghost identifier

Withn is not an identifier — it appears in no design doc and no source file

plan A22, B073; also TODO_LIST.md and docs/planning/2026-10-03_03-43_*.md

The canonical name is WithCriticalServices (code + naming-integrity.md line 30 + DOMAIN_LANGUAGE.md). Withn is an unpronounceable, un-greppable mangled abbreviation that lives only in TODO_LIST and two plan documents. Whoever executes B073 ("Withn alias-vs-rename decision row") must first reverse-engineer what token was meant.

Fix Cite WithCriticalServices and its actual rename question; scrub Withn from TODO_LIST and both plan docs. Annotate, don't blanket-edit (docs-health ANNOTATE discipline).
H4 · Unexpanded + collision

CV is never expanded — and the repo already uses CV to mean something else

plan A11, B043–B045; collision at docs/start-validation-design.md:79

"CV bump" presumes the reader knows which fleet repo CV is; TODO_LIST and consumer-verification.md never expand it either. Meanwhile docs/start-validation-design.md uses "(CV)" for environment-conditional sets — a second, unrelated CV. A newcomer greps "CV" and gets two wrong answers.

Fix Expand the repo name with a link at first use in the plan; rename the start-validation usage to "conditional sets".
