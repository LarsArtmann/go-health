Make Intent a First-Class Artifact

We gate the code by machine and gate the intent by memory. This is a structural review of the working process behind the LarsArtmann fleet, written after a docs-health session that spent most of its effort re-reading timestamped reports by hand — work the fleet already has tools to eliminate.

00Summary

The single most important fact about this process: the product is verified by machines and the plan is verified by humans. The wire format is pinned by a golden file and a CI lockstep check; the reason the next change matters lives in a prose §f list inside a timestamped report. Every session pays a tax to rediscover it — this session read 14 dated files and wrote 321 hand-made annotations to reconstruct intent that a four-line query should have returned.

The good news is that this is not a missing-tool problem. The fleet already ships the whole pipeline: todo-list-ai extracts, go-taskqueue harvests and dispatches, docs-organizer files, and Taskwarrior syncs. What is missing is a handful of connectors — and a decision to move process invariants out of discipline and into architecture.

The bottom line Stop treating "what to do next, why, and cited how" as prose. Give intent the same treatment as the wire format: one machine-readable source of truth, mechanically gated, derived — never duplicated by hand. Three connectors and two gates convert this session's manual work into a query.

◆What's already excellent

This is a mature process with real assets. The redesign reuses them; it does not replace them.

+
Artifacts are mechanically locked openapi-lockstep proves every golden wire key is declared in the spec, as a flake check and a CI job. The repo already believes "derive, don't duplicate" for code.
+
An honest, self-critical report culture Reports carry §a–§g including a "TOTALLY FUCKED UP" section. The raw material for process improvement is already being captured — it is simply not being read back by machine.
+
The fleet pipeline already exists go-taskqueue/internal/harvest scans every repo's TODO_LIST.md, enqueues one agent task per open item, and carries citation, provenance, drift and prune machinery. The ledger interface is already load-bearing.
+
Pareto planning with decision gates Plans encode owner gates (G1–G3) with recommended defaults so execution proceeds without stalling. This is the template for every pending decision.
+
Skills carry procedures; gates mirror CI Skills are the operating system (docs-health, linter-building, github-voice). .#gates and .#ci-emulation make local verification match remote.
+
History is preserved, not rewritten The annotate-then-archive convention keeps resolution non-destructive. The archive is trustworthy because nothing in it was forged after the fact.

01The fundamental asymmetry

Look at the two halves of a change. The artifact side is a closed loop: write code → golden test → lockstep gate → CI. The intent side is an open loop: a human decides something, writes it into a report, and hope carries it forward.

Artifact → test → gate → CI   |   Intent → report §f → memory

The consequences are measurable and recur. In this session alone: three doc defects that were pure arithmetic drift (a version line, a changelog link base, an ADR range) had to be found by rereading; a status report's 50-item §f list had to be resolved item by item at ~6 files × ~50 rows; and an unknown number of dated files were simply not read. None of that is judgement work. It is bookkeeping that a query would have returned.

The tell When I proposed a "machine-readable intent ledger," the fleet already had one — go-taskqueue's harvest engine, with SHA citation and drift detection. The real gap is not a ledger; it is the connector from the report corpus into it.

02Findings

Ordered by impact. Each names the failure mode, the evidence from this session or a prior one, and the structural fix.

Blocking · Highest leverage

Intent has no machine-readable source of truth

docs/status/∗.md §f · TODO_LIST.md · ROADMAP.md

Forward intent lives as prose in timestamped reports and as hand-maintained rows in TODO_LIST/ROADMAP. Harvesting it is archaeology: this session read 14 dated files and hand-resolved ~321 items. The same 50-item report lists were re-audited by hand across three consecutive sessions. 

# What we wrote by hand this session:
grep -rL '~~' docs/status/archived/*.md     # completeness by eye
# What should have been one query:
tq harvest --report 2026-10-02 --json | jq '.[] | select(.routed==false)'
Fix: one ledger, machine-derived Treat TODO_LIST.md as the canonical ledger (it already is — tq parses its checkboxes and — P[1-4] markers). Build the report→ledger connector so §f items become rows with citation and provenance, and archive decidability becomes a query.
Blocking · The read half

Reports are write-only; the loop never closes

go-taskqueue/internal/executor · TQ_RESULT protocol

The fleet already models the agent→report link: an executor emits TQ_RESULT: {"report":"docs/status/...md", "next_items":N}. But next_items is a count, not the items. So the report's intent is stored but not ingested — the reader must still open the file and transcribe.

Fix: emit the items, not a count Add a machine-readable NEXT block (or sidecar) to the report contract; extend TQ_RESULT to carry it. Completion and archival then become decidable: a report is archivable when every item is routed and no open task points at it.
Important · Drift class

Doc drift is mechanically checkable but ungated

README.md:11 · CHANGELOG.md link block · FEATURES.md ADR range

Three defects found this session were arithmetic: a stability line stuck at v0.4.0 while latest is v0.4.1; [Unreleased] comparing from the wrong tag and a missing [v0.4.1] link; an ADR range 001..006 that ignored ADR-007. All are derivable from go.mod, git tag, and docs/adr/.

Fix: port the drift alarm The repo already gates the wire format. Add a .#docs-check that asserts stability line == latest tag, [Unreleased] base == latest tag, every tag has a link ref, and the ADR range matches the directory. Gate it beside openapi-lockstep.
Important · Discipline vs architecture

Process invariants live in discipline, not in the machine

"read before edit" · "ALL means ALL" · scope honesty

This session's mistakes were all "forgot / over-claimed" class: an edit attempted before a read, a TOC line dropped while editing, an internal claim of full file coverage that was not literally true. These are not skill failures; they are missing constraints. An environment that makes read-before-edit and scope declaration mandatory turns three of them into impossibilities.

Fix: hooks over willpower Use pre-tool hooks to enforce read-before-edit and to force an explicit scope manifest ("read: N of M; skipped: list") on any "ALL" request. Invariants belong in the harness, not in a checklist a tired agent skips.
Important · Split brains

Split brains recur because nothing forbids them

counts · versions · token names · test helpers

The same fact gets restated in several files and drifts: consumer counts went 9→14→15 across three sessions; an aggregate test helper sevRank duplicated production Status.Rank(); the HTML report kit itself had paired glow-tokens that drifted until they were unified behind one vocabulary and a sync-check.

Fix: the kit's own solution, generalized One source of truth per fact + a sync-check that fails on drift. The kit proved the pattern (vendored copy + --check exit 1). Apply it to doc numbers, counts, and shared helpers.
Important · Concurrency

Multiple writers, unverified commits

docs/status/2026-09-18 §d · the auto-commit daemon

A prior session documented two agent sessions editing one working tree — mixed "heuristic" commits and a red master from a lint break the daemon committed unverified. The queue already serializes work per repo ("at most one in-flight task per repo"); sessions do not.

Fix: one worktree per session, verify-before-commit Enforce a single-writer-per-checkout rule (git worktree per session) and move verification before the commit, not after — a pre-commit gate, not a post-hoc CI run.
Nice to have · Flow

Owner decisions stall sessions

the G1–G3 gate pattern already works

Sessions park on owner calls ("release now or hold?", "who owns this repo?"). The 2026-10-03 plan already solved it: encode the gate with a recommended default and execute unless overridden. Make that universal.

Nice to have · Unit of work

The repo is treated as the unit of work; the fleet is

15 direct + 16 indirect consumers behind two bridges

A go-health change is a fleet event, yet process runs per-repo. Cross-repo follow-ups leak into per-repo TODO_LISTs and stall (CV skew, six unrun suites). Model the fleet as a graph and let the tools carry the edges.

03What the solution could look like

A closed intent loop that mirrors the artifact loop. The capture and execution ends already exist; the redesign adds the two connectors and the gates that keep the loop honest.

intent ├─ capture  todo-list-ai + report §f
├─ ledger  TODO_LIST.md (checkbox + — P[n] grammar)
├─ connector report §f → rows  ← BUILD
├─ queue    go-taskqueue/internal/harvest (citation, drift, prune)
├─ execute  agent pool → report + TQ_RESULT items ← BUILD
├─ file     docs-organizer
└─ sync     Taskwarrior → tasks.home.lan

Migration steps

1

Freeze the intent schema on the existing grammar

Adopt TODO_LIST.md as the canonical ledger. Define the row grammar the fleet already parses (checkbox, — P[1-4], a citation annotation carrying report + file:line + git SHA). No new file, no new format.

2

Build the report→ledger extractor

Turn docs-health HARVEST into a script: parse a report's §f, emit ledger rows with provenance, dedupe against existing rows. This is the connector that replaces the session's manual transcription.

3

Extend the report contract from count to items

Give reports a machine-readable NEXT block; widen TQ_RESULT to carry it. Archival then follows from a query: no open task, every item routed ⇒ archivable.

4

Port the drift alarm into the gate sweep

One .#docs-check: version line == latest tag, changelog base == latest tag, ADR range == directory, counts derived not stated. Add to .#gates next to openapi-lockstep.

5

Move process invariants into the harness

Pre-tool hook: read-before-edit. Scope hook: "ALL" requires an explicit read/skip manifest. Pre-commit gate: no unverified commit. These convert repeated discipline failures into impossibilities.

6

Single-writer orchestration

One git worktree per session; let the queue own per-repo serialization. This retires the mixed-commit / red-master class documented on 2026-09-18.

7

Funnel + mirror

Make todo-list-ai → TODO_LIST → tq the default intake, docs-organizer the filing step, and Taskwarrior the human cockpit mirroring the ledger. One truth, several views.

05Guardrails to hold the line

Six invariants that, if enforced, prevent the whole defect class.

One source of truth per fact If two files state it, one is derived. Split brains are banned by construction.
Derive, don't duplicate Counts, versions, ranges come from code/tags/dirs, and a gate re-derives them.
Read the prior report first Session step 0 is the previous report. It converts "implement X" into "verify + close + execute follow-ups."
Encode process, don't remember it Read-before-edit, scope manifests, verify-before-commit are hooks, not habits.
Decide with defaults Every owner gate ships a recommended default and executes unless overridden.
Fleet-first, repo-second Treat cross-repo work as the default unit; the repo is a node.
