03Type Models & Libraries

Type models: reuse the designed v0.6 shapes — do not improvise

The right type-model improvements already exist as written, verified designs; inventing ad-hoc types in a docs+tests session would be scope creep against the breaking-change window they were scoped for:

Typed ServiceName identity (docs/servicename-design.md) — kills the stringly-typed source-name contract; one shared merge primitive (docs/merge-unification-design.md) — replaces the aggregate + federation merge twins so worst-of/namespacing/overlay rules live in exactly one place; CheckFunc vs HealthCheckFunc disambiguation (docs/naming-integrity.md) — staged rename table. All three are staged for the v0.6 window with call-site inventories and mechanical rewrite plans; executing them piecemeal now would break the fleet for zero incremental value.

Libraries: zero-dependency is the architecture — stdlib covers every need

go-health's single-dependency rule (ADR-001/002; one dep: samber/do) makes most "add a well-established library" instincts wrong here by design. The honest library decisions for today's work: stdlib testing/f + httptest for the new tests (matching the repo's three existing fuzz targets); the drift gate as plain bash + git (no YAML parser, no new flake input — the checks are grep-level assertions over living docs); the skill-default ginkgo/Gomega BDD stack is deliberately overridden by CONTRIBUTING's no-test-framework rule. Rejected temptation: a YAML library to parse ci.yml — nothing today needs it.
