## Short version (social / Discussions)

**go-health v0.1.2 is out** — a Kubernetes health-probe SDK for samber/do v2
with the three-probe pattern (liveness / readiness / startup), criticality
classification, background caching, and an aggregate sub-package that merges
N in-process probes into one health surface.

v0.1.2 fixes a fuzz-found bug: invalid UTF-8 in `WithInstanceID` turned every
health endpoint into HTTP 500. Also new since v0.1.0: programmatic health
API (`Status`/`Alive`/`Ready`/`AwaitReady`), `WithEvaluationHook` metrics
seam, `WithLiveThrottle` flood protection, instance IDs, a method-set guard,
JSON round-trip + golden + fuzz test hardening (99.7% coverage), and an
OpenAPI spec.

## Longer version (GitHub Discussions / blog)

- **What it is:** drop-in health probes for samber/do v2 injectors. Liveness
  never checks dependencies (no restart cascades), readiness gates on
  critical services only (warn = 200 degraded, fail = 503), startup latches
  once and stops re-checking. Everything is served from a lock-free
  background cache so kubelet polls never hammer your dependencies.
- **v0.1.1 highlights:** `WithInstanceID` (replica attribution),
  `WithAllowedMethods` method-set guard (405 + sorted Allow), fail-closed
  panic recovery, `encoding/json/v2` wire with golden-file lockstep.
- **v0.1.2 highlights:** the instance_id UTF-8 fix (found by the new marshal
  fuzzer), an aggregate merge-invariants fuzzer, JSON round-trip property
  test, seven new godoc examples, and per-commit CI with a new OpenAPI job.
- **Verification culture:** 99.7% statement coverage, three fuzz targets,
  race-clean suite, do-analyzer audit at zero anti-pattern findings, and a
  `nix run .#gates` one-command sweep that mirrors CI exactly.
