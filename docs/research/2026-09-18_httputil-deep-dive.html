00Summary

httputil is the ecosystem's most broadly adopted infrastructure library — and it is used superbly. Every middleware family appears in production somewhere: JSON responses (×59), security headers (×53), CSRF (×41), keyed rate limiting (×38+), middleware chains (×32), reverse proxy (×29), request IDs, logging, recovery, CORS, compression, and the httpspec contract-test library — with near-zero usage of anything removed or deprecated in production code. Version currency is the weak axis: v1.2.0 shipped two days ago, 55% of modules already sit on it, but 11 live projects remain on pre-v1.0 releases that predate the v1.1.0 API removals — and two of the fleet's own files still call the removed symbols, one of them a test suite that cannot compile against its own pinned version.

The bottom line Utilization is exemplary (92/100); the work is two concrete hazard fixes (library-policy's broken tests, nsfw-classifier's one removed-API line) and a mechanical 34-module currency sweep — which, as a side effect, closes the go-etag laggard list from the companion audit in the same bump.

01Findings

Ordered by impact. Findings 1–2 are compile hazards proven statically; 3–4 are currency debt.

Blocking · broken today

library-policy's httpapi tests cannot compile against its own pinned httputil v1.2.0

library-policy/cmd/library-policy/internal/httpapi/middleware_test.go:133,140 · go.sum holds only httputil v1.2.0

The test calls httputil.NewTokenBucketLimiter, httputil.RateLimit, and httputil.RateLimitConfig — all removed in v1.1.0 (verified: zero occurrences in the v1.2.0 tag source; go.sum contains no older version that could supply them). Any go vet/go test of that package fails to build. This slipped through because the module requires go ≥ 1.27 while the local toolchain is 1.26.7 (GOTOOLCHAIN=local) — the compile check could not run where this audit stood. 

// Before (removed API)
limiter, err := httputil.NewTokenBucketLimiter(2, 2)
httputil.RateLimit(httputil.RateLimitConfig{Limiter: limiter})

// After (docs/migrating-to-keyed-rate-limiter.md)
mw := httputil.KeyedRateLimiterMiddleware(
    httputil.NewKeyedRateLimiter(cfg),
    httputil.KeyExtractorFromClientIP(2, 2),
)
Fix Migrate the test to KeyedRateLimiterMiddleware per the shipped migration guide, then re-run the package's gates under the go 1.27 toolchain the module requires.
Important · upgrade blocker

nsfw-classifier still calls the removed httputil.ETag adapter in production

nsfw-classifier/internal/server/server.go:391 · pinned at httputil v0.12.0 (pre-removal, so it builds today)

httputil.ETag(etag.DefaultETagConfig()) — the adapter v1.1.0 deleted as a pure passthrough. The file already imports go-etag/server, so the swap is one line and the middleware behavior is byte-identical. This is also the module the companion go-etag audit flagged; this fix unblocks both upgrades at once. 

// server.go:391 — before / after
httputil.ETag(etag.DefaultETagConfig()),
etag.New(etag.DefaultETagConfig()),
Fix Swap the line, bump httputil v0.12.0 → v1.2.0, go mod tidy; go-etag rises to v0.3.1 in the same step.

23 direct/indirect pins incl. AI-Speed-Test, bank-sync, blog, browser-history, ChastityAPI, e-invoicing ×2, overview, RedditParse, storbi, Zlota44, plugmarket ×3

v1.1.1 is docs/chore-only (verified: its delta touches RELEASE.md and status docs, no library code), so these modules are functionally on v1.1.0. What v1.2.0 adds that they lack: r.Pattern propagation through request-forking middleware (otelhttp spans collapsed to bare GET without it), the AbsentEncoding compression policy (health probes and minimal clients without Accept-Encoding now get identity instead of compressed bytes), CSRF construction hardening, and CORSConfig.AllowPrivateNetwork for Chrome PNA/LNA preflights.

Recommendation Mechanical go get httputil@v1.2.0 sweep; budget an extra look at any consumer whose clients omit Accept-Encoding (the one behavioral change, covered by the migration guide).
