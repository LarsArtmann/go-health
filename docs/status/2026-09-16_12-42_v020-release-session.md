**What could I have done better?**

1. Asked for one explicit confirmation before the tag push. It worked because every gate was green — but that is luck's contribution to a good outcome, not process.

Requires a standing commit authorization I don't have — so I flagged, didn't act. The story lives in the tag message + CHANGELOG, so this is history-quality, not correctness.

**What could I still improve?**

1. Claim hygiene: never encode externally-sourced claims into published artifacts without first-hand re-execution (verify-external-claims is inbound verification — I used it for skills, not for my own release notes).
2. A project release runbook + `nix run .#release-verify` app so the clean-dir `go get` + build + proxy check is one command instead of ad-hoc shell.
3. A pkg.go.dev render watchdog step in that runbook (see b1 — 2h20m and counting).

## e) WHAT WE SHOULD IMPROVE

1. **Claim verification before publishing** — any externally-sourced claim (prior sessions, TODO_LIST, status reports) gets re-executed before it enters a release body, README, or AGENTS.md. d1 is the concrete instance.
2. **Release confirmation protocol** — one message before the irreversible step: "Gates green, CI green, cutting v0.2.0 at f6c583d — confirm?" Even when the user's message reads as authorization. Releases are the one place where a 30-second round trip is cheaper than a permanent mistake.
3. **Explicit release-prep commits** — the tag points at a daemon "heuristic" commit. If Lars grants standing commit authorization for release prep, the story lands in `git log` where bisect and archaeology live. Otherwise, accept and rely on tag message + CHANGELOG (current de facto policy — but it should be a decision, not a default).
4. **One-command release verification** — `nix run .#release-verify <tag>`: clean-dir `go get` + build both packages + `go list -m -versions` check + pkg.go.dev probe. Removes ad-hoc shell from a procedure that will repeat.
5. **pkg.go.dev indexing** — my `/fetch` GET requests 404'd; research whether the trigger needs POST, and add a "+24h render check" row to the runbook rather than retrying in-session for 7 minutes.
6. **Announcement draft belongs in the release checklist** — it was forgotten because no checklist contained it (see c1, e4).
