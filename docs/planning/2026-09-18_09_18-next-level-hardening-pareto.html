00Summary

go-health is a two-package SDK (health, health/aggregate) whose single-probe surface is unusually complete for an alpha: three kubelet probes, lock-free caching, shutdown awareness, panic recovery, per-check metadata, deterministic wire format, fuzzing, and a static OpenAPI spec. The remaining leverage is not more single-probe features. It is finishing the aggregate as a deployment surface, proving the merge algebra in CI, and turning the existing observability seam into an alerting seam.

01Thesis

The gap is composition, not features

Every primitive a production probe needs already ships and is tested. What is missing is the layer that lets one process present its whole health as a single, diagnosable surface, with the guarantees behind it enforced automatically rather than asserted in prose.

The aggregate is half a citizen

health.Probe exposes Healthz(), Status(), Ready(), and WalkReady()-style accessors. The aggregate exposes three handlers and CachedResponse() — but no single-endpoint handler and no per-source roll-up. A deployment whose entry point is one load balancer URL cannot use it as the front door, and a dashboard must re-fold source/check prefixes itself.

Correctness is claimed, not continuously proven

The merge invariants (collision-free keys, worst-of status, absorbing shutdown) are documented and example-tested. Passing examples are not an algebra. This session adds property tests and benchmarks; the missing half is a CI lockstep between the golden wire fixtures and the OpenAPI spec.

021% → 51% · Aggregate first-class

Three additive changes complete the aggregate as a deployable surface. All three already have written design notes, so the decisions are made and only implementation remains.

Highest leverage

Aggregate.Healthz() — one URL per process

docs/aggregate-healthz-design.md (new)

Worst-of-N in a single 200/503 answer: 503 while any source is booting, the merged roll-up is fail, or any source is draining; warn stays 200. Reuses StartupComplete() and CachedResponse(), so it adds no state and no freshness semantics of its own.

Highest leverage

Aggregate.SourceStatuses() — per-source roll-up

docs/aggregate-per-source-visibility-design.md

Answers "is source api healthy overall?" without the consumer folding prefixes. One atomic load per source; zero wire change.

Correctness UX

errors.Join in aggregate.New

docs/errors-join-design.md (spike verified)

Report every invalid source at once instead of failing on the first. errors.Is against the sentinels is unchanged; messages become multi-line, which belongs in a minor release with a changelog callout.

034% → 64% · Evidence + alerting

Shipped this session: the merge algebra is now a test

aggregate/aggregate_property_test.go enumerates every source topology of up to three distinct cached states (pass, warn, fail, shutting down, never-started) and asserts idempotence, source-order commutativity, namespaced-union completeness and disjointness, worst-of status/shutdown/latency, absorbing shutdown, and handler-status mirroring — 425 subtests, all green.

Shipped this session: the blind spots are measured

BenchmarkAggregateHandlers (HTTP path), BenchmarkEvaluate_Scaling (evaluation vs. check count), and BenchmarkTransitionTrackerStamp (the per-batch Since pass) fill the gaps the FEATURES table admitted were unmeasured. Baselines are recorded.

New capability

WithTransitionHook — alerting on state changes

probe.go (needs design note first)

transitionTracker already observes every status change to stamp since. Exposing an OnTransition(from, to Check) callback converts that observation into the missing alerting primitive: "db went fail→pass" without polling or an external diff loop. Design note required (severity mapping, ordering under overlapping batches, panic isolation).

Guardrail

OpenAPI ↔ golden-fixture lockstep in CI

docs/openapi.yaml, handlers_json_test.go

Both the spec and the golden files describe the same wire format, and nothing keeps them in step. A CI check that derives field presence from the golden fixtures and compares it to the spec turns "manual eyeball" into a failing job.

Adoption

healthtest — consumer test helpers

new sub-package

A tiny package with a fake batch builder, a recording HealthRecorder, and readiness assertions removes the boilerplate every consumer writes to test their probes. Design note + owner decision needed before adding public surface.
